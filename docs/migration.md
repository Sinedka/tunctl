# Переход со старого vpn.nix

В изученном локальном файле OpenVPN загружает `/etc/openvpn/client.ovpn`, IPv6 выключается глобально, DIRECT опирается на UID 1999, метку 1, таблицу 100 и периодическое копирование шлюза. DNS принудительно переключается на dnsmasq. Утилита vpn-profile, импорт и active.ovpn в этой версии отсутствуют. На ранее установленной машине эти артефакты могут существовать отдельно.

1. Сохраните защищённую резервную копию `/etc/openvpn`, относительных файлов сертификатов и учётных данных. Посмотрите фактическую цель ссылок через `readlink -f`. Старый каталог профилей можно оставить на месте.
2. Соберите **до смены сети** новое поколение с обоими модулями vpnctl. В конфигурации этого поколения удалите импорт старого vpn.nix. Проверьте, кто управляет DNS, наличие IPv6 в ядре, занятость таблицы 30201 и соответствующих меток.
3. Выполните переключение поколения из локальной консоли. Новый модуль не удаляет старые файлы и не использует UID 1999. Если старые маршруты сохранились после остановки таймера, безопаснее загрузить новое поколение заново. Не очищайте произвольную таблицу 100, она может использоваться другими службами.
4. Для закрытого root-каталога администратор может выполнить `sudo vpnctl validate /etc/openvpn/profiles` и `sudo vpnctl import /etc/openvpn/profiles`. Для одного файла используйте `sudo vpnctl import /etc/openvpn/client.ovpn`. Содержимое читается при выполнении команды. TUI запускается от обычного пользователя.
5. Выберите профиль, подключитесь, сравните VPN и DIRECT, проверьте DNS и IPv6. Старый active.ovpn автоматически не импортируется как выбранный сервер. Список исключений переносится явно через NixOS или Home Manager.

## Восстановление

`vpnctl disconnect` останавливает клиент. При постоянном kill switch блокировка обычного трафика после этого ожидаема. `vpnctl reset` возвращает пользовательские исключения из Home Manager. При неправильных адресах DNS или политике измените системный модуль и активируйте исправленное поколение. Нерабочее соединение и ошибка rollback отображаются в status. Для диагностики системы:

```sh
systemctl status vpnctl.socket vpnctl-routing vpnctl-session vpnctl-tunnel
journalctl -b -u vpnctl-tunnel -u vpnctl-dns -u dnsmasq
ip -4 route show table 30201
ip -6 rule show
```

Если сеть нужна для сборки исправления, используйте локальную консоль и предыдущее поколение:

```sh
sudo nixos-rebuild switch --rollback
```

## Удаление

Отключите соединение, уберите оба модуля и их настройки из конфигурации, примените NixOS и Home Manager. Это снимает постоянный фильтр, останавливает сокет, таймер, DNS upstream и управляемый туннель. Загрузка очищенного поколения гарантирует удаление эфемерных ресурсов ядра и восстанавливает DNS по декларации хоста. Проверьте `ip rule`, `nft list tables` и `/etc/resolv.conf`. Архив профилей в `/var/lib/vpnctl` и пользовательские настройки сохраняются. Удалять их имеет смысл отдельно после проверки резервной копии.
