# Выбор маршрута

Область действия — исходящие IP-пакеты локального хоста. Контейнеры и ВМ с пересылкой через FORWARD требуют отдельной политики. Зарезервированы интерфейс `vpnctl0`, таблица и приоритет `30201`, таблицы nftables `inet vpnctl` и `inet vpnctl_session`. Исходная физическая таблица main принадлежит NetworkManager, dhcpcd или networkd.

| Приоритет | Совпадение | Действие |
|---|---|---|
| 1 | Loopback, сокет OpenVPN с SO_MARK 0x7653, bootstrap DNS endpoint, DHCP и необходимые IPv6 Neighbor Discovery | Локальный или физический путь |
| 1 | Внешний TCP/UDP на 53 и 853 | VPN, включая приложения DIRECT |
| 2 | Cgroup сокета или родительская slice | VPN 0x7651 или DIRECT 0x7652 |
| 3 | Статические DIRECT CIDR администратора, затем пользовательские CIDR по порядку | Первое совпадение |
| 4 | Адрес в DNS-наборе VPN, затем DIRECT | В конфликте общих IP выигрывает VPN |
| 5 | Остальной трафик | VPN |

Когда у туннеля есть IPv4-адрес, VPNCTL резервирует также таблицу и приоритет `30200`. Правило `iif lo fwmark 0/0xffffffff` направляет первый выбор маршрута локального сокета в эту таблицу. Её default задаёт интерфейс и адрес источника туннеля. У транспорта OpenVPN уже есть собственная метка. При исчезновении интерфейса ядро удаляет маршрут, а при остановке службы VPNCTL снимает правило.

Цепочка типа route выполняет классификацию в OUTPUT. Итоговая метка VPN инициирует повторный поиск в таблице 30201. Там находятся default через TUN и резервный unreachable с большим metric. У семейства без туннельного адреса остаётся unreachable. DIRECT и сам транспорт используют физический маршрут. Если правило DIRECT переключило IPv4-сокет с адресом туннеля на физический интерфейс, masquerade подставляет адрес этого интерфейса. Фильтр kill switch проверяет фактический выходной интерфейс после выбора маршрута.

Пока туннель отключён, системный kill switch сохраняет разрешённые адресные и прикладные исключения. Доменное исключение живёт до TTL. Новый внешний DNS-ответ требует доступного DNS через VPN. При выключенном постоянном kill switch явная команда disconnect освобождает фильтр сессии. Исключения работают только для трафика, для которого в физической сети существует маршрут.

## DNS и приложения

dnsmasq служит системным локальным резолвером. Его кеш для этой схемы выключен. UDP/TCP upstream `vpnctl-dns` на 127.0.0.1:53071 принимает DNS-сообщения, отправляет запрос настроенному серверу и следует цепочке CNAME в полученном ответе. Для каждого A/AAAA выставляется timeout с минимумом TTL по цепочке и верхней границей 300 секунд. При TTL 0 адрес не сохраняется. Обновление набора происходит до ответа клиенту, ядро удаляет просроченные элементы. DNS-запрос к имени самого VPN перед подключением отдельно посылается только на `dns.bootstrapDNS` с меткой transport. Пустой список отключает этот способ разрешения и подходит для числовых endpoint.

Правило `example.org` охватывает имя и поддомены, `*.example.org` охватывает только поддомены. Для одного запроса выбирается первое подходящее доменное правило администратора, затем пользователя. Для уже разрешённого IP действует таблица приоритетов выше. При CDN, собственном кеше, прокси, внешнем DoH/DoT или общем IP фактический набор может отличаться от ожиданий пользователя. Соединение с таким адресом невозможно достоверно связать с конкретным HTTP hostname на уровне IP. Собственный DoH внутри DIRECT-приложения также может идти по физической сети.

Привязка приложения основана на cgroup v2 в момент создания сокета. HM запускает приложение через `systemd-run --user --scope --slice=...`. Перед exec клиент обновляет классификатор, когда slice уже существует. Потомки наследуют cgroup. Для произвольно запущенного процесса и переданного между процессами сокета гарантировать совпадение по имени программы нельзя. Перезапустите приложение из сгенерированного launcher. Приложения, которые запускают отдельный user service через D-Bus, требуют настройки Slice у этого сервиса. Пользовательский namespace и отдельный UID для GUI не нужны.

## Проверка

```sh
ip -4 rule show
ip -6 rule show
ip route get 1.1.1.1 mark 0x7651
ip route get 1.1.1.1 mark 0x7652
sudo nft list table inet vpnctl
systemd-cgls --user
dig example.org
sudo nft list set inet vpnctl domains4
```

`route get` показывает результат ядра **для указанной метки**. Для проверки конкретного приложения выполните запрос из его scope и сравните адрес, видимый внешнему серверу. DIRECT-тест запрашивает маршрут ядра до адреса цели с меткой DIRECT и привязывает сокет к найденному устройству. Для имени HTTPS-сервера выбранный адрес также закрепляется в curl. На хостах с VRF, собственными более приоритетными ip rules или другими владельцами меток требуется согласование политик.

При полном пересоздании таблицы nftables сбрасываются динамические DNS-элементы и правила приложений. Backend заново устанавливает правила при следующем refresh (обычно до десяти секунд), адреса доменов возвращаются после новых DNS-ответов. При административной перезагрузке firewall учитывайте это окно для пересекающихся исключений. Можно синхронно вызвать `vpnctl refresh` и повторить нужные DNS-запросы. Вкладки правил сверяют метки правил с фактически установленными цепочками ядра.
